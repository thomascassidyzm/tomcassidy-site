# Security audit — 2026-09-20

A foreign model (Astra/GPT-6) cold-read this repo's server surface without
running any code and produced 14 claims. This document verifies each against
the live source (file:line), fixes the ones that were confirmed and in scope,
and records the rest with what was actually true.

**Top finding, not on Astra's original list** (see Claim 12): the guide's math
renderer ran KaTeX with `trust: true` and the resulting HTML reached the
client via `innerHTML` unescaped — a genuine XSS, closed below. The same bug
is confirmed present in the two sibling repos (`~/distinction-physics`,
`~/configuration-economics`) and is **not fixed there** — this dispatch is
scoped to tomcassidy-site only. Flagged under "Needs Tom" below.

Not touched by this dispatch (out of scope: different repos).

- **Env-rotation answer (Claim 7): rotating `ANTHROPIC_API_KEY`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `SUPABASE_URL`, or `SUPABASE_SERVICE_ROLE_KEY` in the Vercel dashboard alone does NOT take effect until the next deploy** — for `ANTHROPIC_API_KEY` and `VAPID_PUBLIC_KEY` because those two files read `import.meta.env` only; for the other three because the shared `env()` helper's `\|\|` precedence favours the build-time value whenever it's non-empty. If a secret is ever rotated for real (compromise response, routine hygiene), a redeploy must follow immediately — this is not automatic today.

The shim is now fixed to stop losing a partial migration (Claim 13) but is otherwise unchanged — deletion (the file, its call in `cron/coach.ts`, and the three `PUSH_SUBSCRIPTION`/`PROGRAM_START_DATE`/`WEEKLY_GOAL` Vercel vars) is still a Tom action once he's checked Supabase directly.
- **Claim 9's byte-limit-while-reading half** (validating body size while streaming, not just after full parse) was recorded as a bigger change and not built — the current `MAX_ENDPOINT_LENGTH`/`MAX_KEY_LENGTH` checks in `subscribe.ts` happen after `request.json()` has already fully parsed the body, same as before.
- **Claim 5's management-credential redesign** (replacing the raw endpoint-as-credential with something that isn't itself a URL-loggable secret) is a real hardening step, recorded, not built.
- **The push-service allowlist (Claim 3 fix) is deliberately generous** — if a real browser vendor's push host is missing from `ALLOWED_PUSH_HOST_SUFFIXES` in `subscribe.ts`, that vendor's users would silently stop being able to subscribe. Worth a quiet eye on subscribe-endpoint error rates by browser after this ships.
